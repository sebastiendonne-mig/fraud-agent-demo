Détection de fraude et recours : un agent sous contrôle

Saisissez un sinistre fictif ou choisissez un scénario. Des règles déterministes calculent le score et le routage ; un agent Claude n'intervient que si c'est utile, propose une décision, et un humain valide.

Comment ça marche
  1. Règles déterministes. Quatre règles explicables (adresse IP partagée, réseau de réparateurs, déclaration précoce, montant atypique) calculent un score sur 50. C'est un port fidèle du script Python du projet, testé à l'identique.
  2. Triage. Le score donne le routage : traitement automatique sous 15, investigation de 15 à 29, alerte SIU à partir de 30. Ces seuils sont un choix de démonstration, non calibré sur des données réelles. Le routage est une règle métier : l'agent ne peut pas le modifier.
  3. Agent à outils sans effet réel. Claude n'est appelé que si le dossier n'est pas en traitement automatique ou si un rapport de police est fourni. Ses outils ne font que lire le portefeuille fictif ou calculer : aucun envoi, aucune écriture.
  4. Décision typée. L'agent termine par une proposition structurée. Le serveur recalcule les chiffres (montant du recours, seuil) et signale toute correction.
  5. Validation humaine. Rien n'est finalisé sans votre décision. Le dossier final est un brouillon : aucun envoi réel.
  6. Limites. Démonstrateur sur données entièrement fictives, pas un outil de production. Le nombre d'analyses réelles par jour est limité ; au-delà, un rejeu signalé est affiché. Les seuils de démonstration ne sont pas calibrés sur des données réelles. Le montant de recours affiché est un montant brut : la franchise n'est pas traitée dans cette démo.
  7. Chiffres mesurés le 01/10/2026. Environ 0,02 à 0,03 $ par analyse complète (plus élevé au premier appel après une période d'inactivité, cache de prompt froid), 6 à 10 s pour l'analyse et 3 à 6 s pour la finalisation, 1 à 2 tours selon le dossier, mesurés sur 3 scénarios fictifs.
